# K0 —— Neighbor-Constrained Anatomy Prior

用户 2026-10-09 规格（路线①）：Contact 的 `CONTACT_CONSTRAINT_CONFLICT` 不是
Contact 的错，是上游解剖先验的**近远中整体过宽**。在
`H.1 Anatomy Prior → **K0** → J.2 Frozen → Contact Hardened` 之间加一层，
**J.2 算法与 Contact Gate 都不动**，只换 J.2 的 anatomy 输入。

## 1. 已实现（`app/geometry/crown_outer/proximal_fit.py` + `tools/run_proximal_fit_case.py`）

* **Neighbor Clearance Envelope**：`tgt = closest + n̂·clearance`（与 Contact 引擎
  同构），不是"投到邻牙表面"。
* **四类硬锁**：margin/cervical、occlusal core、buccal core、lingual core；
  自由区只有 proximal wall + transition band（沿用已验证的法向/带宽语义，
  不用 z 分位粗切）。
* **低频收窄场**：逐点需求 |Δ| 在 free 区做 Laplacian 平滑（幅值低频），
  方向沿 Δ；α line search × 硬几何门（零新增自交 / 非流形不新增 / 翻面 0 /
  锁定区位移 0），**并对原始网格累计判定**（逐步判定会累积出折叠）。
* **先测后修**：`--fit` 不给就只出账。

## 2. 真实例账（只测不改，`cf_b1b73bae221211b1`）

| 侧 | 可编辑先验顶点 | 穿透顶点 | 穿透 p50 | **穿透 p95** | max |
|---|---:|---:|---:|---:|---:|
| mesial | 549 | 163 | 0.335 | **1.129** | 1.187 |

**预测的 ~1mm 系统性过宽成立**（两侧 p95 都在 1.1mm 量级）。
轴向归因：distal 只有 76/1836 个点在 |n̂·â|≥0.5 的"沿轴有效"范围内
→ 纯轴向平移模型不足以覆盖（v1 实测只降 mesial 1.129→1.074、distal 1.114→1.098）。

## 3. 结构性根因（本轮最关键的发现）

`stage_outer_h1` 的放置是**按 margin 环大小做等比缩放**：

```
uniform_scale = 1.10218        ← 模板整体放大 10.2%
```

冠的近远中宽度因此被撑大 ~1.0–1.1mm，**正好等于实测穿透量**。
放置过程**完全没有看邻牙**——这不是求解器问题，是"用一个标量把模板放到
患者 margin 上"这个做法本身的局限。

## 4. 修正量本身是对的（机制已验证）

方向修对（`Δ = closest + n̂·clearance − v`，符号写反会越推越深）之后：

| 侧 | α=1.0 后穿透 p95 | 几何门 |
|---|---:|---|
| mesial | 1.129 → **0.235** | ✗ 329 片 severe 翻面 |
| distal | 1.114 → **0.275** | ✗ 464 片 + 1170 新自交 |

即：**"收 ~1mm 就能进 0.2mm Gate"被证实**，但**当前带宽下施加不了**——
transition band 只有 6 环（≈1.8mm 弧长），1mm 位移的应变远超网格能承受的限度；
另外方向场逐点取"最近 patch 面法向"，在最近面切换处是**跳变**的，也在制造折叠。

## 5. 归因（按用户 §12 的 A/B/C）

**B：还是整片 ~1mm → 上游 envelope/width model 不够**，且根因已具体定位到
`uniform_scale`（等比放置）。不是局部小块（不是 A），也没有到"必须大幅破坏
anatomy 才塞得进去"（不是 C）。

## 6. 下一步候选（需决策）

1. **邻牙感知放置（推荐）**：把 `uniform_scale` 的单标量放置换成
   **三轴/带间隙约束的放置** —— 近远中方向按"邻牙可用间隙"定宽，
   颊舌/咬合按解剖定形。改动落在 `placement`/`generator` 的 H.1 生成，
   K0 这层的 envelope 账正好当它的验收口径。**一次解决，且不违反
   "颊舌保持 anatomy"**。
2. **加宽 K0 形变带**：把 transition band 拉到全冠（含颊舌参与），
   同时平滑方向场。代价是违反用户 §7 的"颊舌 core 硬锁"，且应变是否仍可接受
   未验证。
3. 两者结合：放置先解决主体宽度，K0 再收尾残余（0.2mm 级）。

## 7. 当前状态

K0 工具与账已就位（`tools/run_proximal_fit_case.py --fit`）。**fit 目前无法通过
几何门**，如实报 `REVIEW_REQUIRED`，不折叠换指标。Contact 侧仍是

## 结论：放置层的**预缩放**不足以解决（已量化）

但还是只让半宽动 0.24mm。原因是**下游的 margin 硬约束 Laplacian 把冠体拉回去了**：
margin 环被硬钉在患者颈缘（尺寸不受我们的 MD 缩放影响），冠体只有咬合弱锚，
于是形变解把"被预缩小的冠体"又撑回接近模板的形状。

也就是说：**近远中收窄必须作为 H.1 形变求解里的约束项，而不是只做摆放前的预缩放。**
这是"越大的形状变化越应该发生在 generation 阶段"的直接推论，属于 H.2 的下一步，
而不是下游模块的职责。

## 已实现

  避免 raw face normal 在三角形切换处跳变）、`build_active_constraints`

  只推不拉，不会做成邻牙反模）、`solve_proximal_constrained`（active-set 迭代，

**结论：约束被精确满足（resid → 0.0000），但审计口径的穿透没有改善

即：**"把约束塞进系统"这一步做对了（机制成立），但约束的"目标本身"与验收口径不一致
→ 解到目标也不改善穿透。**

## 定位出的三处口径问题（都已修 / 已记档）

1. **root 顶点混进 active set**：模板根部是硬锚（不可动），实测 566 个 active 里

   （剔除后 resid 立刻 → 0.0000）。
2. **几何门参考系错**：拿 `placed` 当参考会把 margin 拟合本身的合规形变
   （颈环要动 2.8mm）算成"H.2.1 拖动锁定区"。已改为 reference = **H.1 输出**，
   锁定区交给求解器自报的 margin 残差。
3. **patch 法向定向口径不一致（新发现，重要）**：`orient_against_crown`
   （冠法向点积）与引擎在用的 `_orient_patches`（质心法）**符号相反** ——
   换用它会让 H.1 基线从 1.04/1.11 变成 1.78/1.83，等于换把尺。已统一到**引擎口径**
   （全链 Gate 是 Contact，口径必须跟它对账）。

## 下一步单点（不该扩散）

把约束的**目标**换成与审计**同一个**精确口径：`patch.closest()`（精确最近面 +
该面法向，子 0.01mm）取代 `NeighborEnvelope` 的"最近顶点 + 平滑法向"近似。

# H.2.1 收口：报表混网格已确认并修复；归因从 C 改为 **B**

用户 2026-10-09 §1–§4。**根因不是顶点域，是报表把"被拒候选的诊断"和"实际交付网格
的指标"混在了同一列**：两版首轮都被 Gate 拒绝 → 都返回同一份 `placed` → 穿透数字
逐位相同。修完之后真相完全变了。

## 修了什么（一个提交，不扫权重、不动求解器、不放宽 Gate）

* **返回语义**：`accepted_v` 初值 = `reference_v`（合法 H.1），**不是 `placed`**；
  被拒候选只留诊断、不更新 accepted；`placed` 只是线性化中心。
* **报表三列**：`baseline=H.1 / candidate=被拒候选 / accepted=实际交付`，
  **每列的每个指标都从该列自己的网格重算**（含几何、颊舌拖动、edgeΔ）。
* **冻结域**：`audit_ids`（全部冠表面顶点）/ `editable_ids`（未锁定的近远中候选）
  在 H.1 基线上生成一次；`active` 每轮更新。**审计域不缩到候选集**，
  `audit − editable` 按 margin/cervical/occlusal/root/not_proximal_land 分账（含面积）。
* **符号冻结**：开跑前固定 `normal_sign`，审计只读（不再在测量时改 patch 符号）。
* **两个量分开**：`penetration = max(0, −signed)`、`deficit = max(0, clearance − signed)`
  （旧代码写 `max(0, −signed − clearance)`，既不是穿透也不是欠缺）。
* **同一候选重查询**：固定目标残差 / 重查询后的穿透与欠缺 / 最近面切换比例 / 冻结符号。

# H.2.1 per-iteration α 回溯（本轮）

用户 2026-10-09：只做 α 回溯；目标 / 权重 / 冻结域 / Gate 都不动。
口径修正（用户指出）：`deficit ≈ 0.05mm` = **穿透基本消除、尚未达 clearance**，
"间隙真满足"不成立 —— 已按此改口径。

## 实现

`trial = accepted + α·(candidate − accepted)`，α = 1, 1/2, 1/4, 1/8, 1/16（有限回溯）。
每个 trial 必须同时满足：

```
相对上一步 新增自交 = 0（severe 口径）
相对 H.1   累计翻面 = 0（severe 口径）
锁定区位移 ≤ 既定容差（solve_laplacian 的 margin 残差量级，不是 1e-9 浮点噪声）
冻结 editable 域上 deficit 改善、max 不恶化（**不是**动态 active 子集的 p95）
```
接受后重查询、更新 active set 再求下一轮；**全部 α 失败 → 保留上一次 accepted 并明确报阻断**。

| J.2 | 1.0842 | 1.0636 | **再膨胀 mesial +0.089**；残留 **1 micro 自交**（severe 0） |

J.2 的再膨胀是本轮**第二次独立复现**（上一链 0.9676→1.0921，本链 0.9950→1.0842）
—— 最低厚度 envelope 不知道邻牙空间，出形后按自己的下限把 proximal 撑回去。
这就是用户 2026-10-09 预判的 "J.2 有可能再次把 proximal 往外顶"，两次实测都成立。
架构含义：**邻牙空间 envelope 必须在基础构造（与最低厚度 envelope 同一层）里
参与，而不是先出形再靠后面的形变层往回修**。

### 判决（用户已锁 A→B→C）


含义：该案患者可用近远中空间（≈9.2mm）比牙库任何同 FDI 基型小 1.7–2.2mm；
在**不改锁定验收**的前提下，三条许可路线都无法把近接穿透降进 Contact 可修范围。
