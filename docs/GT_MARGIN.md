# 真值颈缘提取（GT Cervical Margin）

`app/geometry/gt_margin.py` — `extract_gt_crown_margin()`

**这是验收真值提取器，不是患者 Prep 的自动 Margin 算法。** 两者要分开：

| | 输入 | 面对的困难 |
|---|---|---|
| **本模块** | 已完工的最终冠 + 基台 | 无噪声。任务是从一个已知正确的成品里找出 intaglio ↔ exterior 的交界缝 |
| 患者 Margin 算法 | Prep / Abutment 扫描 | 扫描噪声、牙龈遮挡、裁切边界、无先验 |

---

## 1. 为什么必须换掉旧方法

旧 `_metrics.cervical_margin()` 取"真值冠最低 0.4 mm 带的顶点"。实测该假设不成立：

| 取带宽度 | 方位角覆盖 | 是否闭环 |
|---|---|---|
| 0.2 mm | 15/24 | ❌ 残弧 |
| 0.4 mm | 16/24 | ❌ 残弧 |
| 0.8 mm | 19/24 | ❌ 残弧 |
| 1.5 mm | 24/24 | ✅ 但已跨 1.5 mm 高度 |

所以"最低 Z 带""法向正负""拟合平面切一圈"三种做法全部出局：
颈缘是**空间三维闭环**，不能假设近平面，也不能靠世界 Z。

**也不能"选最大环"。** FDI36 的冠实测 **χ = 0（genus 1）**，有**两条**缝
（颈缘 + 螺丝通道口）：用旧的面法向符号法，"最大环"是 246 点、位于 z≈11.1、
半径 1.1 —— 那是**螺丝通道口的边缘**。

---

## 2. 实际采用的判据：朝向场符号，无阈值

对每个冠面片取到 support 的**精确最近点**（`trimesh.proximity.closest_point`），算

```
cos = n · (nearest_support_point − face_centroid) / |...|
```

语义：面片是否"朝向"support。

- 外表面：材料在内侧，法向背离 support → `cos < 0`
- 内表面：材料在外侧，法向指向 support → `cos > 0`

**标签直接取 `sign(cos)`。** 没有阈值，没有图割，没有标签传播。

这不是偷懒，是有实测依据的选择。FDI36：

```
近 Support (d ≤ 0.16):   10275 面，其中 cos > 0.1 的 99.9%   → 内表面
远 Support (d ≥ 0.5):    29264 面，其中 cos > 0.1 的  0.0%   → 外表面
距离歧义带 (0.16<d<0.5):    887 面（2.2%）
```

朝向场的符号在两端的纯度接近 100%；它的零交叉是**内蕴**的，不需要选分离点。
而距离场本身是双峰的（内表面 0.047–0.151 mm，中间一个明显空隙，外表面 0.8–3.15 mm），
说明内外表面在几何上确实清晰可分。

`sign(cos)` 的结果：

```
内表面 10482   外表面 29944
界面边 314     界面顶点 314     度数分布 {2: 314}     ← 全部二度，干净流形缝
检出环 2（正好等于 genus 1 应有的两条缝）
```

### 为什么不用距离阈值硬切

exocad 数据实测 `CementGapThickness` 跨 **0 → 0.08**，还有 Start / Top /
Additional spacing 变体。任何固定距离阈值都会在某些病例上切错。朝向场没有这个问题。

`fitting_params` 若提供，只写入诊断，**不参与标签判定**。

## 3. 环选择：主判据是"包围"

FDI36 实测三条候选：

| 环 | 点数 | 周长 mm | 轴向相对位置 | 半径 mean/max | 到 Support 中位 mm | **包围比例** |
|---|---|---|---|---|---|---|
| 0 | 208 | 10.70 | 0.71（咬合侧） | 1.29 / 2.01 | 0.071 | **0.095** |
| 1 | **102** | **21.76** | **0.10（颈侧）** | **3.36 / 3.83** | 0.237 | **1.000** |
| 2 | 4 | 0.46 | 0.76 | 3.23 / 3.32 | 0.901 | 0.000 |

环 1 = 颈缘；环 0 = 螺丝通道口；环 2 = 拓扑噪声伪影（周长 0.46 mm，被下限滤掉）。

**主判据**：环的投影是否包围**该环自身轴向高度附近**的 support 截面 —— 10 倍分离度。

### 两个反直觉的实测（都试过，都不判别）

**① "离 support 近"是反向的。** 通道口到 support 的中位距离 **0.071** 比颈缘的
**0.237** 更近 —— 它就在基台顶部正上方。这个直觉判据不能用。

**② "沿 −axis 是否被冠自身遮挡"不判别。** 通道口与内腔同轴，向下的射线穿孔后
直接出颈缘开口。实测两个环的被挡比例**都是 0.000**。

**③ "是否包含 support 中心"不够。** 通道口与基台同轴，包含中心对它同样成立。
必须是**包围截面**，不是"包含一点"。

## 4. 输出

```python
MarginExtractionResult(
    points, edge_ids,
    is_closed, is_simple,
    perimeter_mm, spacing_cv,
    azimuth_coverage,
    support_distance_stats,
    confidence,
    status,          # OK | REVIEW_REQUIRED | FAILED
    diagnostics,
)
```

**不包含 `margin_plane_height` / `plane_normal` 之类的核心语义字段。**
最佳拟合平面只出现在 `diagnostics.best_fit_plane` 里，并带 `_note` 说明不得压平。
（有一个测试专门断言这三个字段不在输出顶层。）

理由：即使本病例的缝接近平面（残差 max 0.043 mm），那是**该病例的性质**，
不是保证 —— 沿龈下轮廓走的 finish line 并不平面。做成输出字段下游就会去用。

## 5. 一个必须记录的 off-by-one

初次实现把正确的颈缘环**整条拒绝**，理由是"自交 1 处"，而且两条环都恰好报 1 处。

根因：为了闭合而 `np.vstack([points, points[:1]])` **append 了首个点**，
数组末尾多出一个重复端点。于是段 0 `(v0→v1)` 与闭合段 `(v_{m-1}→v0)` 在几何上
共享 `v0`，但模运算的邻接判断 `(j+1)%n == i` 认不出"末尾那个点就是首点"，
把它们当成非相邻线段，距离为 0 → 误报自交。

修正：**契约是"传开环点列"**，helper 内部用模索引。
`test_self_intersection_helper_contract` 把误用的后果也钉住了（传闭合点列会报 1），
防止将来有人给 helper 加容差"绕过"而不是修正调用方。

## 6. 验收（7 条 + 补充，共 13 项）

`tests/acceptance/geometry/test_gt_margin_extraction.py`

| # | 断言 | 实测 |
|---|---|---|
| ① | 恰好一条候选通过 gate | ✅（genus 1 有 2 条缝，靠语义选出颈缘） |
| ② | `is_closed == True` | ✅ |
| ③ | `is_simple == True` | ✅ |
| ④ | 自交数 == 0 | ✅ |
| ⑤ | 方位角覆盖 ≥ 24/24 | ✅ **1.000**（旧方法 0.667） |
| ⑥ | 投影包围 support 截面 | ✅ **1.000**（通道口 0.095） |
| ⑦ | 刚性等变 | ✅ 点集 Hausdorff < 1e-6；标量指标 < 1e-6 |

补充：拓扑被报告而非假定（χ=0、genus=1、界面顶点全二度）；被拒候选必须带理由
留存；包围比例必须有**数量级**区分度（防止阈值碰巧通过）；平面只作诊断；
自交 helper 的契约。

### 为什么刚性等变这条必须有

它是唯一能拦住"依赖世界坐标轴"这类缺陷的测试。本项目在就位方向求解器上已经因此
抓到一个真 bug（`if axis[2] < 0` 世界 Z 符号约定，使倒凹比在刚体变换下从 0.844
跳到 0.156 而轴夹角仍显示 0.000°）。

## 7. 修正后的真值质量与下游影响

```
status                 OK
is_closed / is_simple  True / True
n_points               102
perimeter_mm           21.7583
azimuth_coverage       1.000
spacing_cv             0.127      （旧方法 1.89）
n_self_intersections   0
genus                  1           （2 条缝，正确选出颈缘）
best_fit_plane 残差     max 0.043 mm（旧方法 0.191）
best_fit_plane 倾角     偏离 +Z 11.67°   ← 关键
confidence             0.9899
```

**边缘平面倾角 11.67° 是一个重要发现。** 旧的"最低 0.4 mm 带"给出一个几乎水平的面
（偏离 +Z **0.80°**）。而基台自身拟合轴偏离 +Z **12.9°** —— 两者一致，
因为**边缘平面本就垂直于基台轴线**。用错平面切分"就位面"会把倒凹统计的作用域放错。

### 被推翻的两个结论

**① 曾断言该基台有"轴对称外扩 emergence profile，相对任何轴都是倒凹，
所以此刻 OK 是错答案"。已推翻。** 用正确 Margin 后最优轴倒凹比 **0.117 < 0.15**，
求解器报 **OK**。此前报 REVIEW_REQUIRED 是错 Margin 的产物。
记录在 `baseline.json` 的 `retracted_expectations`。

**② 曾说"颈缘是斜的三维曲线、相对最佳拟合平面残差 max 3.83 mm、平面假设不成立"。
已推翻。** 那个 3.83 mm 是坏提取（残弧）的产物，不是颈缘本身的性质 ——
真实缝的平面残差 max 只有 **0.043 mm**。

（第 ② 条同时说明：**"不要压平"这个设计决定仍然正确**，但理由要从
"本病例不平面"改成"平面与否是病例的性质，不能假设"。有一例近似平面，
不代表下一例也是。）

## 8. 度量版本与不可比性

Margin 真值的提取方式变了，因此**任何用到 Margin 的度量，其定义都变了**。

`baseline.json` 的 `metric_versions` 记录每项的定义版本；
旧数值记录在 `legacy_measurement`：

```
margin_band_clearance_median_mm        legacy 0.515  ->  v2 0.2542
supra_margin_clearance_p95_mm          legacy 0.965  ->  v2 0.529
isolated_chain_outer_deviation_p95_mm  legacy 0.976  ->  v2 0.8784
```

**这些变化不能归因给几何算法改善** —— 里面混了 Margin 真值修正。
要比较必须用同一 `metric_version` 重跑。三项仍不达标，仍挂在
`known_defects` 上（它们是真缺陷：blockout 投影柱、厚度修正），
但**数值本身已不可与旧值直接对话**。

这正是下一步做 `build_blockout_cutter` 之前的必要铺垫：
现在 Axis 与 Margin 都固定了，改 blockout 时 clearance 的变化才能唯一归因。
