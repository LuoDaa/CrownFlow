# 目标牙定位与 Prep/Support 分割

上游（exocad / 3Shape）只告诉你目标牙位是 `FDI46`，不告诉你 46 在扫描网格里的
XYZ。这个模块把**牙位编号**变成**网格上的区域**，再把该区域切成一个能交给
Axis / Margin 的独立 support 网格。

```
locate_target_tooth(jaw_mesh, 46, user_seed=点) -> ToothLocalizationResult
extract_support(jaw_mesh, target_region, target_fdi=46) -> SupportSegmentationResult
```

---

## 1. 双模式，以及自动模式当前的真实状态

| 模式 | 状态 |
|---|---|
| `user_seed=点`（操作员点一下目标牙） | **已实现、已验收** |
| 无 `user_seed`（自动） | **未实现**：返回 `REVIEW_REQUIRED` + 实测理由 |

自动模式不做，不是偷懒，是实测不支持。没有训练过的牙实例检测器时，
自动定位的唯一纯几何路径是"把参考牙列刚性配准到扫描，再读目标牙的位置"。
实测 FDI36 病例的 `Unsectioned_LowerJaw`（其实是绕 FDI36 的 **sectioned
cast**，只含约 5-6 颗牙，不是整颌）上，多起点 ICP 的前 5 名残差只差 10%：

```
1.034 / 1.136 / 1.146 / 1.188 / 1.193 mm
```

判别度不足，取第一名等于把随机结果说成"找到了"。参考牙列 16 颗 vs 局部扫描
5-6 颗，本身也不该配准。所以自动模式要求"整颌牙弓 + 判别度足够的配准"
两个条件同时成立 —— 这正是需求里"自动置信度不足时让用户只点一下 46"
所描述的情形。**当前不会输出任何自动坐标。**

## 2. 核心机制：凹陷代价测地线

从种子出发做测地线扩张，但**经过凹脊（邻接沟、龈沟）的行程代价被放大**，
于是区域自然停在凹谷处：

```
edge_weight = |edge| × (1 + VALLEY_GAIN × deviation)
deviation   = max(valley_strength − FLAT_ANGLE_RAD/π, 0)
硬屏障      : valley_strength > VALLEY_BLOCK 的边直接断开（权重 inf）
```

`valley_strength` 由**凹/凸判据**给出：对一个邻接面对取面 1 的法向 `n1` 与
"面 2 形心 − 面 1 形心" `d`，`dot(n1, d) < 0` 为凸、`> 0` 为凹，
强度 = 二面角偏离量 / π。凸边一律记 0 —— **牙尖和边缘嵴是凸脊，不是分割边界**。

这解决了 `roi.spherical_roi` 的根本问题：它按**直线距离**取面，
半径一大就切进邻牙和牙龈，半径一小就丢掉龈缘。

### 几个必须踩过才知道的点

- **阈值要能拦住 90° 交界的台阶。** `VALLEY_BLOCK = 0.42`
  （≈ 偏离平面 76°）。原先取 0.60（≈108°）太尖锐，连"圆柱预备体与牙龈的
  直角交界"都拦不住，区域会顺壁上爬再漫进牙龈。
- **定位半径必须大到能走到解剖边界。** 从牙冠中心到颈缘的测地行程 =
  半径 + 冠高，一颗磨牙约 5.5 + 8 = 13.5 mm。`REGION_SCALE = 1.10`
  （半径 12.1 mm）才够。取 0.72 时区域是**被半径截断**的而不是被凹脊拦住的，
  切口落在平滑面上 —— 实测合成夹具上切口前沿凹度 0.000，而凹脊就在 1.3 mm 外。
- **"边界是否依附凹谷"要看切口前沿，不能看区域自己的边界顶点。**
  硬屏障把凹脊上的**边**断开后，区域边界落在屏障**内侧**的平滑面上，
  边界顶点凹度恒为 0。`cut_front_strength` 取区域外两圈邻接顶点才对。
- **切割半径的含义取决于源是什么。** 源是已定位的**区域**（几千个顶点）时，
  测地线从整个区域出发，半径 = 余量就够；源只是一个**种子点**时，
  半径必须自己铺到冠部（冠宽/2 + 余量）。混用会把 support 撑大好几倍
  （实测 112 mm² → 662 mm²）。
- **`face_adjacency` 装的是面索引对**，共享边的顶点在 `face_adjacency_edges`。
  把前者当顶点索引用会直接越界。
- **面积参考要用球冠 `2πr²`，不能用咬合面足迹 `πr²`。**
  足迹漏掉了牙冠侧面，而 support 恰恰包含侧面。实测 FDI36 预备体
  （r 5.5、高 4）真实表面约 215 mm²，用足迹算是 76 mm²，比值 3.06
  会被误判成"带进了邻牙"。
- **支撑体源点不能简单取"最近顶点"。** 操作员完全可能正好点在凹脊上 ——
  实测最近顶点凹谷强度 0.90，它的每条边都被硬屏障断开，区域只剩它自己。
  `resolve_seed_sources` 取"种子附近且不在硬屏障凹脊上"的一小片当源。

## 3. 验收数字（面板与 checks）

`extract_support` 返回的全部是可复核的数字，不达标就 `REVIEW_REQUIRED`：

| 检查 | 含义 |
|---|---|
| `single_connected_component` | 单连通 |
| `target_retention` | 目标区域被完整保留的比例（下限 0.98） |
| `boundary_valley_strength_mean` | **切口前沿**平均凹度（下限 0.22） |
| `boundary_is_anatomical` | 边界是否依附解剖凹谷（False = 度量切割） |
| `convex_cut_fraction` | 切口走在凸面上的比例 |
| `n_boundary_loops` | 边界环数（理想 1） |
| `area_ratio_vs_crown` | support 面积 / 球冠参考面积 |

## 4. 实测

### 合成夹具（可提交 Git）

"牙龈平板 + 预备体凸台"，交界是**精确 90°** 的凹脊（显式"环 + 缝合"构造，
不是高度场台阶 —— 台阶要把壁塞进一个网格间距里，二面角会随分辨率漂移）。

    scale=0.72  定位 OK        切口前沿 0.238   边界依附凹谷 ✓
    scale=0.90  定位 REVIEW    切口前沿 0.170   切进凸面 → 报出来
    support     单连通 1 环    目标保留 1.000   解剖边界 ✓

### 真实 FDI36 病例

真值来自同一坐标系里的基台模型 `1629-王煜 0.stl` —— 实测基台顶点到整颌表面
的中位距离 2e-6 mm，说明两者同坐标系，且**整颌网格里确实包含了那颗被扫描的
基台**。所以"定位到的位置就是基台所在的位置"不是自说自话。

    locate  : OK，置信度 0.689，区域半径 12.10 mm，切口前沿凹度 0.401
    support : REVIEW_REQUIRED，置信度 0.930
              单连通 ✓   目标保留 0.9998 ✓   面积比 2.07 ✓   边界依附凹脊 ✓
              未过项：**8 条边界环**（理想 1 条）
    整颌网格：闭合流形（每条边恰好 2 个面，0 条边界边）

## 5. 已知未解决（要如实说）

- **自动模式未实现**（见 §1）。
- **support 补片不是"一条边界的圆盘"**：真实病例上边界是 8 条环，
  所以状态是 `REVIEW_REQUIRED`。已做的缓解是 `fill_mask_pinholes`
  （补上被包围的针孔顶点，边界环 10 → 8、连通分量 2 → 1）；
  根因是闭合流形上按测地半径切割时区域会绕过窄颈形成额外边界环。
  **没有解决，只是被报出来。**
- **近远中接触面的精确分离做不到。** 两牙接触处是平滑鞍部而非尖锐凹脊，
  纯局部几何切不开 —— 这是牙齿分割的公开难题（CrownSegger 一类需要训练模型）。
  本模块报告越界程度（`area_ratio_vs_crown` / `convex_cut_fraction`），
  而不是假装解决了它。
- **一条被推翻的中间结论，留在这里备查。** 中途我曾断言"基台/牙龈交界没有
  凹脊"，理由是实测 max 只有 0.054。**那是错的**：那个数字来自只有 **11** 个
  顶点的样本（用 `d < 0.3 mm` 匹配基台顶点到整颌顶点，龈方端只剩 11 个）。
  容差放宽到 0.5 mm 后：

      龈方端 30%：n=46    mean 0.547  p90 0.862  max 0.873
      龈方端 45%：n=1176  mean 0.226  p90 0.868  max 0.971

  交界上的凹脊很强，这个病例**可以**依附解剖边界。
  教训：拿"最大值"下结论之前先看样本量。

### 合成夹具锁住的规则

1. 凹谷场只标凹脊，不标凸脊（壁底 > 阈值，壁顶 < 0.05）
2. **刚性变换等变**：位置随变换一致改变（< 1e-6），面积不变（< 2%），状态不变
3. 分辨率稳定性（改方位向分辨率，面积漂移 < 6%）
4. 低置信度 fail-loud
5. 切割半径与"源是否为区域"配套

## 7. 代码结构

```
app/geometry/tooth_location.py
  face_pair_convex / vertex_valley_strength   凹/凸判据（纯几何，等变）
  geodesic_distances                          凹陷代价 + 硬屏障的测地线
  cut_front_strength                          切口前沿凹度（不是边界顶点凹度）
  fill_mask_pinholes                          掩码针孔填充
  boundary_edges / boundary_loop_count        可靠的边界环计数
  resolve_seed_sources                        种子 -> 源顶点（绕开凹脊）
  locate_target_tooth                         定位（种子模式 / 自动模式）
  extract_support                             切割 + 验收 checks
```

自算 `boundary_edges` 而不是用 `mesh.outline()`：`outline()` 在边界较碎时返回
一堆互不相连的短链，`len(entities)` 当"边界环数"用会报出 3/9/11 这种假数字。
