## 3. 逐项说明

### 3.1 参数真值 —— 可用，且是当前最有价值的资产

9 个 `.constructionInfo`（分属 8 个病例目录），共 **38 条牙位记录**、
**145 个参数类型**、每牙位 47–134 个参数。

这是本地唯一**能立刻用上**的标注：它给出了真实的临床/加工参数，
使参数系统不必猜值。详见 `PARAMETERS.md`。

8 个含参数的病例：

```
82404020415薛文爱   82404060702张哲森   82404060754武淑琴   82404090703邱治钧
82404110733         82404140726         MY10075901          MY10075903
```

其余 7 个目录（含 `薛文爱` 这个重复目录）没有参数文件。

### 3.2 几何回归 —— 只有约 2 例

**这是最容易被高估的一项。** STL 命名是 `XXX-A组 (n).stl` 这类
**无角色标签的序列**（(1)–(9)，1–37 MB），无法自动判定哪个是上颌、哪个是预备体。

| 病例 | 情况 |
|---|---|
| `1629-王煜` | ✅ **唯一**有完整语义分类的病例：上下颌、最终基台、最终牙冠、解剖参考、口扫、种植组件，且 `99_记录/分类文件索引.csv` 逐文件说明用途 |
| `82404110733` | ✅ 有语义化 STL 名：`吴宝刚-24-modeldie.stl` 等 per-tooth 代型、`-bridge_slm_cad.stl`、`-modelbase.stl` |
| 其余 12 例 | ❌ STL 无角色标签 |
| `82404110766`、`82404140676张寿山` | ❌ 完全没有 STL |

`1629-王煜` 是唯一的几何验收 fixture，坐标已核实：基台、解剖参考、最终牙冠
都在 `X 19–29 / Y −1–10 / Z 3–13 mm` 范围内，适合在同一坐标系比较。

### 3.3 咬合 —— 约 1 例

`1629-王煜` 的上下颌天然在同一坐标系（实测对颌最小距离 0.005 mm）。

**除此之外没有咬合空间变换的真值**：15 例的 `.matrix4` 是固定的坐标系约定变换
（15 个文件内容逐字节一致），不是逐病例咬合配准。见 `EXOCAD_IMPORTER.md` §4。

所以：

### 3.5 重复与泄露风险

**同一订单出现在两个目录**：`82404020415薛文爱` 与 `薛文爱` 同属订单
`03c3329e-87f8-43f3-93d5-c5c9537ee4d1`。

15 个目录归为 **14 个订单组**。训练/验证拆分**必须按 `source_order_id` 分组**，
按目录随机拆会让同一口扫描同时进入训练集和验证集。

### 3.6 不可解码的部分

**59 个 `.DCM` 全部报错**：

```
HPSEncryptionError: Encryption key not found.
Set the HPS_ENCRYPTION_KEY environment variable or provide the key.
```

3Shape CE 加密。虽然没有 `HPS_ENCRYPTION_KEY` 读不出网格，但错误信息是明确的
（不会静默产出垃圾）。

`.dentalCAD`（51 个，最大 ~100 MB）是二进制容器，可能含 Margin 曲线与就位方向真值，
但需要专门的格式反向工程 —— 这不是短期收益。

`.3ox` 是 UTF-16 XML，已可解析（提供 `OrderID` / `ScanSource` / PHI 字段）。

## 4. `1629-王煜` 基准病例

### 文件清单（`99_记录/分类文件索引.csv`）

| 作用 | 文件 |
|---|---|
| 下颌 | `01_主要病例模型/Unsectioned_LowerJaw.stl` |
| 上颌 | `01_主要病例模型/Unsectioned_UpperJaw.stl` |
| **最终基台** | `01_主要病例模型/1629-王煜 0.stl` |
| **最终牙冠** | `01_主要病例模型/1629-王煜 1.stl` |
| 解剖参考 | `03_牙冠解剖参考/UNN19.stl` |
| 微笑库牙冠参考 | `03_牙冠解剖参考/Crown Unn19.stl` |
| 预备体扫描 | `02_口扫数据/PreparationScan.stl` |
| 基台对齐扫描 | `02_口扫数据/AbutmentAlignmentScan.stl` |
| 对颌扫描 | `02_口扫数据/AntagonistScan.stl` |

牙位是 **FDI 36**（左下第一磨牙），种植基台单冠。

### 实测几何

| 对象 | z 范围 | 体积 | 备注 |
|---|---|---|---|
| 基台 | 3.49–10.82 | 96.3 mm³ | 颈部窄（r≈1.2，z 3.5–5.2）→ 外扩（z 5.7–6.7）→ 近圆柱（r≈2.9，z 6.7–9.7）→ 咬合收缩 |
| 真值冠 | 5.63–12.50 | 210.8 mm³ | 含内表面（壳） |
| 对颌扫描 | 10.4–25.5 | — | 佐证咬合方向为 +Z |

**该基台有一个轴对称外扩的 emergence profile**（半角 ≈ 49°），
它相对任何就位轴都是倒凹，只能靠 blockout 处理。这一点是
"不能用 +Z 误差当验收判据"的原因之一，详见 `INSERTION_AXIS.md` §6。

### fixture 局限：已修复

**当前验收使用的 Margin 真值已改为从真值冠提取的 intaglio ↔ exterior 真实交界缝**
（`app/geometry/gt_margin.py`，见 `docs/GT_MARGIN.md`）。

旧的"最低 0.4 mm 带"方法实测只覆盖 16/24 方位角（**残弧不是闭环**），
spacing_cv 1.89。新方法的真值质量：

```
闭环 True   简单 True   自交 0   方位角覆盖 1.000   周长 21.76 mm   spacing_cv 0.127
genus 1（2 条缝，正确选出颈缘）   边缘平面偏离 +Z 11.67°   置信度 0.99
```

边缘平面倾角 11.67° 与基台自身拟合轴（12.9°）一致 —— 边缘平面本就垂直于基台轴线。
旧的近似水平带（0.80°）把"就位面"的作用域放错了位置，曾因此虚高倒凹比
（0.214 → 修正后 0.117）并让求解器误报 REVIEW_REQUIRED。

**注意度量不可比**：`baseline.json` 的 `metric_versions` 记录了定义版本，
旧数值在 `legacy_measurement`。
